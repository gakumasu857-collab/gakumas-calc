# スケジュールの「開発側のデフォルト」をスプシで決める（シートの内容の案）

状態: **案の段階**（2026-09-18）。コード側の読み取りはまだ作っていません。オーナーの確認が取れたら作ります。

## 何を決めるシートか

プロデュース（発動回数のテンプレ）ごとに、「どの週（日）で、おでかけ・相談・差し入れ（活動支給）・特別指導のどれを踏むか」の
**完全初期の状態**を決めるシートです。今は、スプシの回数（お出かけ◯回・相談◯回…）から
「差し入れ → 相談 → おでかけ → 特別指導の順に、前の週から埋める」という決まりでコードが自動で組み立てています
（`src/data/scheduleCalendar.ts` の `inferChoices`）。このフォルダの3つのファイルは、**その今の結果をそのまま書き出したもの**です。

## 追加するタブ（今のスプレッドシートに新しいタブとして足す）

| タブ名 | 中身のファイル | 対応する今のタブ |
|---|---|---|

入れ方: ファイルをメモ帳などで開いて全部コピー → 新しいタブの **A1** に貼り付け（タブ区切りなので、そのままセルに分かれます）。

> 新しいタブは、コード側の準備ができるまで同期の対象に入らないので、先に足しても今のサイト・`update-all.cmd` には影響しません。
> （今ある `abilityCounts◯◯` タブの中に行を足す形だと、名前のチェック（`check:labels`）に引っかかって `update-all.cmd` が止まるので、別タブにしています。）

## シートの形

```
        A列             B列                        C列〜（プロデュースの列。abilityCounts◯◯ タブと同じ並び）
1行目   （空）          （空）                      プラン（センス・好印象・やる気・強気・全力）
2行目   スケジュール     選べる行動                  プロデュース名（花ロボ(黄) など）
3行目〜 選抜1日目 など   相談／差し入れ／特別指導     その週（日）に踏むもの
```

- **1・2行目**は `abilityCounts◯◯` タブの1・2行目と同じ（プラン行＋名前行）。列の並びも同じにします。
- **A列**は週（日）の名前。H.I.F は「選抜1日目」「本戦3日目」、N.I.A・初は「3週目」のように書きます。
  選べる行動が1つもない週（レッスン・授業・営業・試験だけの週）は行を作りません。
- **B列「選べる行動」**は、その週に選べるものの一覧（見るためだけの列。コードは読み飛ばします）。
- **C列〜のセル**には、次のどれか1つを書きます。**空欄＝その週は何も踏まない**。
  - `おでかけ`／`相談`／`差し入れ`（初は `活動支給`）／`特別指導`
  - その週の「選べる行動」に無いものを書いた場合は、コード側でエラーにして知らせます（作る予定の仕組み）。
  - 表記ゆれ（`お出かけ`、`活動支給・差し入れ`）は同じものとして読みます。

## コード側で作る予定の仕組み（確認後）

1. 同期するタブに3つを足す（`worker/lib/sync.js` の `GRID_TABS`、`wrangler.toml` の `SHEET_TABS`）。
2. `scripts/generateAbilityCounts.mjs` でこのタブも読み、`src/data/generated/abilityCounts.json` にテンプレごとの選択を入れる。
3. テンプレのスケジュールの既定を、今の「回数からの推測」ではなく**このシートの値**にする
   （利用者が画面で選び直した分は、今までどおりブラウザに保存された選択が優先）。
4. おでかけ・相談・差し入れ（活動支給）・特別指導の**回数はこのシートの選択から数える**ので、
   `abilityCounts◯◯` タブの同じ4行（お出かけ・相談・活動支給・差し入れ・特別指導（3回まで））はテンプレでは使わなくなります
   （食い違ったら `check:labels` で知らせる）。
5. プロデュースの列を足すときは、`abilityCounts◯◯` タブとこのタブの両方に同じ列を足します
   （片方にしか無い列は、今までどおり回数からの推測で埋めます）。
