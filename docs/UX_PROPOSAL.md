## 1. いま何が分かりにくいのか（初めて使う人の目線）

実際の画面（`/calc` ほか）と初回利用の流れを追って、つまずきやすい点を洗い出した。

| # | つまずき | 起きていること | 根っこ |
|---|---|---|---|
| 1 | **何から始めればいいか分からない** | 計算ページを開くと「未選択」の黄色い欄が散らばっている。所持状況とメモリーは**別ページ**で入力しないと探索ボタンが押せないが、その順番はヘルプの中にしか書いていない | 「準備 → 実行 → 調整」の順番が画面に現れていない |
| 2 | **ボタンが多くて主役が分からない** | 「理想の評価値編成を求める」「今の踏み方でサポカ編成を最適化」「条件設定」×2（歯車）「全て外す」「画像で保存」… 同じ画面に青いボタンが複数 | 主操作が1つに絞られていない。同じ機能（条件設定）への入口が2つある |
| 3 | **結果がどこに出たか分からない（特にスマホ）** | 評価値・最終ステはデスクトップでは左に固定表示だが、スマホでは入力欄を全部スクロールした**一番下**。押した直後に変化が見えない | 「押す場所」と「結果が出る場所」が離れている |
| 4 | **言葉が難しい** | 発動回数セット・踏み方・寄せ方（軸）・理論評価値・前イベ/後イベ/ステイベ・取得回数・パラボ変換表・審査基準・条件設定… | ツール独自の用語が説明なしで並ぶ。ゲーム内の言葉と一致しないものもある |
| 5 | **画面左端の縦タブ（発動回数／レッスン）に気づかない** | 「ここからが本番」の調整機能が、細い縦タブの中にある | 重要機能が発見しにくい場所にある |
| 6 | **探索後のメッセージが長文** | 「理論評価値 35,318 の組み合わせを…（12,345通りを探索・8.2秒）。寄せ方の比較: DaVi 35,318（採用）／VoDa …」が1段落 | 情報の重要度に差がない。上級者向け情報（軸比較・探索件数）も同列 |
| 7 | **条件設定モーダルが長い** | 7項目が縦に並び、「SP率持ちの最低枚数」「取得回数」など上級者向けと「タイプ割合」など基本の区別がない | 基本／詳細の分け方がない |
| 8 | **ナビの7タブが同じ重さ** | 計算／所持状況／メモリー／アビリティ発動回数／サポカ設定／サポカ点数表／データベース | 「入力するページ」と「見るだけのページ」「上級者向け」が混在 |
| 9 | **何が変わったか分からない** | 探索で編成と踏み方が置き換わるが、前後の差分（どのカードが入れ替わったか、踏み方がどう変わったか）が示されない | 変更のフィードバックがない |
| 10 | **小さな灰色の説明文が多い** | 各ブロックの下に 11px の注記。読まれないか、読むと逆に不安になる | 説明を「置く」ことで解決しようとしている |

## 2. 目指す形（3つの原則）

1. **3ステップで結果が出る**: 「① 持っているものを登録 → ② 育成の前提を選ぶ → ③ 求める」を画面の上に常に出す。
   どこまで済んでいるかが一目で分かり、未完了の項目はその場から埋められる。
2. **主役は1つ・結果はその隣**: 画面に「押すべき青いボタン」は1つだけ。評価値はボタンのすぐそばに出て、押す前後の差が見える。
3. **最初は少なく、必要なら開く**: 基本の操作だけ見せ、細かい調整（条件設定・発動回数・前イベ後イベ・踏み方の手動編集）は
   「詳しく調整」として畳んでおく。上級者は今までどおり全部触れる。

## 4. ナビゲーションと言葉

### 4-1. ナビの整理

| いま | 案 | 理由 |
|---|---|---|
| 計算 | **計算** | メイン。ホームからの入口もここ |
| 所持状況 | **所持状況** | 準備①。準備バーからも飛べる |
| メモリー | **メモリー** | 準備③ |
| アビリティ発動回数 | **発動回数** | 名前を短く。計算ページの「発動回数を調整」からも開ける |
| サポカ設定 | ▾その他 → **サポカ設定（上級者向け）** | 前イベ/後イベの細かい既定・BAN/固定。初回には不要 |
| サポカ点数表 | ▾その他 → **点数表** | 見るだけのページ |
| データベース | ▾その他 → **データベース** | 見るだけのページ |

タブは「入力する順」に並べ、参照系は「その他」にまとめる。ブランド名（プロデュース計算機。2026-09-13 に「サポカ編成計算機」から改名）クリックでホームは今のまま。

### 4-2. 言葉の置き換え（画面上の表記）

| いま | 案 | 補足 |
|---|---|---|
| 理論評価値 | **最大評価値（自動探索）** | 「理論」が何を指すか伝わらない。ボタン名は「理想の編成と踏み方を求める」で統一 |
| 発動回数セット | **育成パターン（発動回数）** | 「センス花ロボ（黄）」などはゲーム内の育成スタイル名なので、パターンと呼ぶ方が近い |
| 踏み方 | **レッスンの踏み方** | 初出は必ず「レッスンの」を付ける |
| 寄せ方（軸）／DaVi | **ステを寄せるタイプ（Da・Vi 寄せ）** | 結果カードの詳細だけに出す |
| 取得回数を制限する | **前イベ・後イベを何回まで発動させるか** | 説明を名前に含める |
| SPレッスン率アップ持ちの最低枚数 | **SP率持ちを何枚入れるか** | 「トレーナーは全タイプに数える」を注記 |
| 条件設定 | **探索の条件** | 「何の設定か」を名前で示す |
| 最終ステータス／プロデュース開始時のステータス | **育成後のステ／開始時のステ** | 短く |
| 審査基準 | そのまま（ゲーム内用語） | ツールチップで「Vo>Da>Vi の順に評価が伸びやすい」など一言 |

用語には**ⓘ のツールチップ**を付け、説明文は本文から外して「ⓘ」に寄せる（灰色の注記を減らす）。

## 5. 段階的な実装計画（機構は変えない）

各段階は独立してリリースできる。上から順に効果／手間の比が高い。

### 段階1（配置と主役の整理・1〜2日）
1. **準備バー**を計算ページ上部に追加（所持状況／前提／メモリーの済・未、未設定へのリンク）。
   既定セーブ「全サポカ完凸」を1クリックで読み込む導線を①に置く。
2. **主役ボタンを1つに**: 「理想の編成と踏み方を求める」＋ ▾（編成だけ／踏み方だけ）＋「探索の条件」。
   サポカ編成カードの青ボタンと2つ目の歯車を外す。
3. **結果カード**の構造化（前後の評価値・入替カード・踏み方・条件チップ・▸詳細）。
   `optMsg` の長文を要素に分ける（データはすべて `AutoOptimizeResult` にある）。
4. **左端タブ → 本文の「踏み方」ブロック**（8レッスンのチップ＋[編集]、発動回数の[調整]）。
5. ナビの並び替え・短縮名・「その他▾」。
6. スマホの**下固定バー**（評価値＋主役ボタン）。

### 段階2（分かりやすさの補強・2〜3日）
7. メモリーの選択を計算ページ内のモーダルで（ライブラリから4枚を選ぶだけ。作成はメモリーページ）。
8. 「探索の条件」モーダルを **基本**（タイプ割合・最低/最高ステ・ステージアイテム）と
   **詳細**（SP率持ち枚数・取得回数・試験補助）の2タブに。
9. 用語のⓘツールチップと、灰色注記の削減（本文は1行、詳細はⓘ）。
10. 結果の「入替」表示: 前の編成と比較して入ったカード／外れたカードを画像つきで。
11. 準備バーの「!」から**その場で埋めるモーダル**（シナリオ／アイドル／育成は今のモーダルを流用）。

### 段階3（体験の仕上げ・任意）
12. 初回だけ出る3画面のガイド（「登録→選ぶ→求める」）と、ヘルプの再編（Q&A形式）。
13. サポカ選択モーダルからその場で凸・所持を直せる（所持状況ページへ行かなくてよい）。
14. 見た目の統一: 文字サイズを 3 段階（見出し／本文／注記）に、色の意味を固定
    （**青＝押す**、**黄＝未設定・注意**、**緑＝条件OK**、**赤＝条件NG／上限超え**）。カードの角丸・影・余白を共通化。
15. 「画像で保存」の出力を、結果カードと同じ構造（評価値・条件・編成・踏み方）に揃える。

## 6. 変えないこと

- 計算式・探索アルゴリズム・保存データの形式（localStorage のキーと中身）は変えない。
- 既存の機能はすべて残す（配置と入口が変わるだけ）。上級者が今やっている操作は同じ手数以下でできるようにする。
- 用語の置き換えは**画面の表記だけ**。コード内の名前（`typeRatio` 等）とドキュメントの用語は据え置き。

## 7. 最初に試す小さな一歩（おすすめ）

段階1の 1・2・3 だけを先にやると、「何をすればいいか」「どこを押すか」「何が起きたか」の3つが解消される。
これだけで初回の体験はかなり変わるはずなので、まずここまでを実装し、利用者の反応を見てから段階2へ進むのがよい。
